# AI常駐型グループチャットアプリ」の要件定義

## 1. アプリケーションの全体構造

### **全体フロー**

1. **ログイン画面:** ユーザー選択 / 新規登録フォーム
2. **会話選択画面:** 過去の会話一覧（ドロップダウン）から選択 / 新規会話作成
3. **チャット画面:** **「チャットエリア（左〜中央）」**と**「要約サイドバー（右）」**の2ペイン構成

### **基本構成**

- **参加者:** 人間数名 ＋ AIサポート（AIHelper）1名（ID: "AIHELPER"、表示名: "AIHelper"）
- **基本コンセプト:** 会話の中から重要な発言だけをユーザーが「目利き」してサイドバー（議事録）へ流し込み、AIがそれを構造化・整理する。

### **ヘッダーに必要なボタン**

- **「新しい会話」:** 新規会話作成
- **「別の会話に移動」:** 過去の会話から選択（ドロップダウン表示）
- **「ユーザー切り替え」:** ログイン画面に戻る
- **「リンクコピー」:** 現在の会話を共有するためのリンク（UI にコピーボタン）
- **その他:** セッション再読み込みボタン

---

## 2. 会話管理

### **会話の作成・参加**

- **conversationId:** UUID で自動生成
- **新規会話作成:** ヘッダーの「新しい会話」ボタン → 会話 ID 自動生成 → 新規 Summary Table レコード作成
- **既存会話への参加:** 「別の会話に移動」ドロップダウン / またはリンク展開（conversationId をクエリパラメータに含める）
- **会話タイトル:** Summary Table から要約を取得し、タイトル情報を表示（ドロップダウン表示用）
  - **要約にはタイトル必須:** AI 要約時のプロンプトに「最初に『# タイトル』形式で会話のタイトルを生成してください」と指示
- **セッション再読み込み:** ヘッダーボタン「セッション再読み込み」で DynamoDB から最新データを再取得

### **会話表示フロー**

1. アプリ起動時に Users Table から conversationIds を取得
2. 各会話の要約テキストから冒頭 20～30 文字をタイトル化（または最初の行を抽出）
3. ドロップダウンリストに「会話①」「会話②」... と表示
4. 選択時に画面全体が切り替わる（完全なページ切り替え）

## 3. 要約サイドバーの機能

- **要約の生成・更新ロジック:**
- **インプット:** 「現在サイドバーにあるテキスト（編集済）」 ＋ 「今回チャットから選択された発言」。
- **AIの挙動:** 過去の全ログは参照せず、渡された情報のみで再構成する。既存の人間による編集内容を尊重し、矛盾や先祖返りを防ぐプロンプトで制御する。
- **要約の形式:** 必ず **「# タイトル」** で始まること（タイトル必須）
- **トピック分類:** AIが「大項目（決定事項、TODOなど）」ごとに自動分類。
- **選択状態の管理:** 各ユーザーが独立した選択状態を保持（AppSync State でリアルタイム管理）。選択範囲は個別ユーザーにのみ表示。

- **操作UI:**
- **追加:** チャットバブルを直接タップしてハイライト（複数選択可）し、サイドバー上部の**「要約に追加」ボタン**で実行。ボタンは1個以上選択しているときのみ押下可能。
- **編集:** 編集開始ボタンを押して開始。保存ボタンで確定。編集中は編集エリアを強調表示する。
- **取消（Undo）:** 直前の「要約に追加」操作を1回分キャンセルし、前の状態に戻す。フロント側で履歴を1段階保持。Lambda 実行中は Undo は無効化。

## 4. AIサポート（相談役）の仕様

### **AIHelper の詳細**

- **ID:** "AIHELPER"（固定）
- **表示名:** "AIHelper"（チャットに表示）
- **ユーザーの意識:** ユーザーからは登録不要、DB 登録も不要（フロント側で固定値として扱う）
- **メッセージ投稿時:** userId "AIHELPER" で自動投稿

- **立ち位置:** 参加者の一人としてチャット内に存在。
- **回答の出力先:** チャット内の吹き出しとして、他の参加者と同様に投稿される。
- **操作UI:** ユーザーの発言入力エリア付近に**4つの定型ボタン**を設置。

### **4つのAI相談ボタン:**

| ボタン名                                 | 実行条件              | Bedrock への入力                  | 説明                                                          |
| ---------------------------------------- | --------------------- | --------------------------------- | ------------------------------------------------------------- |
| **選択したチャットをAI要約**             | メッセージ1個以上選択 | 選択メッセージ + 現在の要約       | 選択したメッセージの内容を要約。相談ボタン3つの基本プロンプト |
| **選択したチャットに対するAI意見**       | メッセージ1個以上選択 | 選択メッセージ + 現在の要約       | 選択したメッセージに対するAIの意見・分析を提示                |
| **入力している内容についてのAI回答**     | 入力欄に テキスト存在 | ユーザー入力テキスト + 現在の要約 | ユーザーが入力中の質問に対するAI回答                          |
| **要約を元にしたネクストアクション提案** | 制限なし              | 現在の要約のみ                    | サイドバーの要約から、次のアクションを提案                    |

## 5. 複数人利用時の制御（排他制御）

### **操作ロックのルール**

**要約実行中（AI要約・AI意見）**

- ロック対象：
  - 「要約に追加」ボタン
  - 「サイドバー編集」ボタン
  - 「選択したチャットをAI要約」ボタン（別のAI要約を同時実行不可）
- 許可される操作：
  - 選択状態の変更（可能）
  - 「AIHelperへの相談」ボタン 3 つ（別途実行可能）
  - 通常のチャット投稿（可能）

**サイドバー編集中**

- ロック対象：
  - 「要約に追加」ボタン
  - 「サイドバー編集」ボタン
  - 「選択したチャットをAI要約」ボタン
- 許可される操作：
  - 選択状態の変更（可能）
  - 「AIHelperへの相談」ボタン 3 つ（別途実行可能）
  - 通常のチャット投稿（可能）

**AIHelper への相談実行中**

- ロック対象：なし（他のユーザーは通常以上に操作可能）
- ただし、**同一キューに入った複数のAIHelper要望は順番に処理される可能性あり（キューイング方式を推奨）**

- **同期タイミング:** 選択中のハイライトは本人にのみ見え、実行ボタンが押された瞬間に全員のサイドバーが更新され、ロックが解ける。
- **ロック解除のルール:**
  - **正常終了:** 要約完了、または保存ボタン押下時に解除。
  - **自動解除:** 3分間のタイムアウト設定。
- **Undo の競合処理:** Lambda 実行中に Undo が押された場合、フロント側で **Undo ボタンを無効化** して、Lambda 完了後に有効化する。

## 6. UI/UXの視覚的フィードバック

### **メッセージ表示順序**

- **時系列順（古い → 新い）で固定**
- **スクロール:** 新しいメッセージが投稿されたとき、自動で最新メッセージまでスクロール追従

### **フィードバック表示**

- **選択中:** メッセージがハイライトされ、選択されていることが視覚的にわかる（個人の選択状態のみ表示）。
- **編集中:** サイドバーの編集エリアが「編集中であること」を強調するデザイン（色、枠線など）。
- **編集中の他ユーザー通知:** 「○○さんが編集中です。」と表示。
- **AI要約処理中の通知:** 「○○さんがチャット①『＊＊＊冒頭15文字くらい』、チャット②『＊＊＊冒頭15文字くらい』...を要約に追加中です。」と表示。
- **AIHelper処理中の通知:** 「AIHelperが〇〇さんの質問に回答中です。」と表示（処理中フラグで表現）。
- **ローディング表示:** 各処理中に適切なローディングアニメーション/スピナーを表示。
- **要約に使われたチャット:** 要約に含められたメッセージの背景色を変更（確認可能にする）。

### **エラーハンドリング**

- **エラーメッセージ投稿:** Lambda 失敗時（Bedrock エラー、タイムアウトなど）、AIHelper 名義でチャットにエラーメッセージを投稿
  - 例: "申し訳ありません。要約生成中にエラーが発生しました: [エラー詳細]"
- **エラーログ:** CloudWatch へ自動記録（デバッグ用）

## 7. ユーザー管理とログインフロー

### **ログイン画面UI**

1. **タイトル:** "AI常駐型グループチャット"
2. **表示内容:**
   - **「ユーザーを選択」** ドロップダウン（登録済みユーザー一覧）
   - **OR** 「新規ユーザー登録」セクション
     - ログイン ID 入力欄
     - 表示名入力欄
     - 「登録」ボタン
3. **操作フロー:**
   - 既存ユーザー選択 → 直接チャット画面へ遷移
   - 新規登録 → ID・表示名入力 → Users Table に保存、DB から最新ユーザーリストを取得

### **ユーザー登録・選択フロー:**

1. **ログイン画面表示:** アプリ起動時 / ヘッダーの「ユーザー切り替え」ボタン押下
2. **登録ユーザー検索:** ``IUserIdとdisplay要件 Table から全ユーザーリストを取得
3. **既存ユーザー選択:** ドロップダウンから選択 → 直接チャット画面
4. **新規ユーザー登録:**
   - ユーザーが **ログイン ID**（一意）と **表示名** を入力
   - Lambda 側で **ログイン ID の重複チェック** を実施
   - 重複していれば登録せず、エラー返却（ログイン画面에 "このIDは既に登録されています" と表示）
   - 重複なければ Users Table に保存、その後チャット画面へ遷移

### **Users Table スキーマ:**

- **PK:** loginId（一意のログイン識別子）
- **displayName:** ユーザーの表示名（チャットに表示される名前）
- **createdAt:** アカウント作成日時
- **conversationIds:** 参加中の会話 ID 配列（複数会話対応）

### **その他の UIL仕様**

- **チャットメッセージ表示:** userId は表示されず、**displayName のみ表示**
- **AIHelperメッセージ:** 固定表示名 "AIHelper" で表示（userId は "AIHELPER" だが、ユーザーには非表示）
- **メッセージの編集・削除:** 現状では **不提供**（将来拡張の候補）
- **テキスト制限:**
  - **サイドバー要約:** 最大 **5000 文字**
  - **チャットメッセージ:** 制限なし（またはWeb標準の2000文字程度）
- **マークダウン対応:** 要約・メッセージともマークダウン表示は任意（プレーンテキスト推奨）
